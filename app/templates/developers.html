L’API PaceForge

Version 1 · 15 novembre 2026

Le principe

Avec une clé personnelle, un script, un tableur ou une application lit tes propres données en JSON : tes plans de course et leurs temps de passage, tes activités et, si tu l’autorises, tes mesures de santé. L’API est en lecture seule : elle ne modifie rien.

Toutes les adresses commencent par {{ base }}/api/v1. Le schéma OpenAPI : /api/v1/openapi.json.

Ta clé

Crée-la dans Réglages › Accès API (adresse e-mail confirmée), {{ max_keys }} clés au plus. Elle s’affiche une seule fois : copie-la aussitôt. Envoie-la dans l’en-tête Authorization, jamais dans l’adresse : une clé passée dans l’URL est refusée.

curl -H "Authorization: Bearer pf_…" {{ base }}/api/v1/me

Une clé donne accès en lecture à tout ce qu’elle couvre. Garde-la secrète, ne la mets ni dans une page web ni dans un dépôt de code, et révoque-la dans Réglages si elle a circulé : elle est refusée aussitôt. Un nouveau mot de passe révoque toutes tes clés.

Les règles communes

  • Limites : {{ per_minute }} requêtes par minute et {{ per_day }} par jour (UTC) et par clé ; {{ plan_quota }} détails de plan par heure et par compte (chacun est recalculé). Au-delà : 429, avec l’en-tête Retry-After en secondes.
  • Format : JSON en UTF-8, noms de champs en anglais, stables dans la version 1. Les ajouts de champs ne changent pas de version ; lis-les sans les exiger.
  • Dates : ISO 8601 avec leur décalage (2026-11-14T08:03:00+01:00), sur ton fuseau pour les activités, sur celui de la course pour les plans.
  • Unités : mètres, secondes, mètres par seconde, battements par minute (bpm), kilogrammes ; la VFC en millisecondes.
  • Pages : limit (50 par défaut, {{ max_page }} au plus) ; la réponse donne next_cursor, à renvoyer en cursor pour la page suivante, null à la fin.

GET /api/v1/plans

Tes plans de course, du plus récent au plus ancien : date, heure de départ, distance, dénivelés et ton objectif (null sans objectif).

curl -H "Authorization: Bearer pf_…" "{{ base }}/api/v1/plans?limit=20"
{{ examples.plans }}

GET /api/v1/plans/{id}

Un plan comme sa page le calcule : l’estimation, le temps visé et, pour chaque point de passage puis l’arrivée, la distance, le dénivelé cumulé, le ravitaillement (water, full, base), l’assistance, le sac, l’arrêt prévu, la barrière horaire et ta marge, le temps que tu as fixé, et le passage de chaque scénario : target (Cible), fast (Optimiste), safe (Sécurité). Chaque passage donne le temps de course (elapsed_s), l’heure (clock, day 0 le jour de la course) et l’instant (at, null sans date de course). basis dit sur quoi le plan repose : objective, pinned (temps fixés), estimate, ou race_day une fois recalé sur un passage réel (Cible seule).

curl -H "Authorization: Bearer pf_…" {{ base }}/api/v1/plans/7
{{ examples.plan }}

GET /api/v1/activities

Tes activités, de la plus récente à la plus ancienne, avec leur résumé et les services qui les ont envoyées. Filtres : since et until (une date AAAA-MM-JJ, jours inclus, ou un instant ISO 8601), sport (run, trail, bike, other, ou un type précis comme TrailRun).

curl -H "Authorization: Bearer pf_…" "{{ base }}/api/v1/activities?since=2026-11-01&sport=trail"

Ces données sont sensibles. Elles ne sont lues qu’avec une clé créée avec « Inclure mes données de santé » et tant que ton consentement aux données de santé est donné : sinon 403, avec le code health_scope_required ou health_consent_required. Retirer ton consentement retire cet accès à toutes tes clés.

Les erreurs

Une erreur répond en JSON : {"detail": "…", "code": "…"}, la phrase en français, le code stable.

StatutCodesQuand
400token_in_url, invalid_cursorUne clé dans l’adresse, un curseur abîmé
401token_missing, token_invalid, token_revokedPas de clé, une clé inconnue ou révoquée
403health_scope_required, health_consent_required, email_unverifiedLes données de santé sans leur accès, une adresse non confirmée
404not_foundRien à cette adresse, ou rien qui soit à toi
405method_not_allowedAutre chose qu’un GET
422invalid_parameterUn paramètre illisible ou hors limites
429rate_limitedUne limite atteinte : attends Retry-After secondes

Le cadre

L’API sert ton usage personnel : lire tes données avec tes clés. Elle est fournie sans garantie de disponibilité, comme le reste du service (conditions d’utilisation) ; ce que PaceForge garde de tes clés est dans la politique de confidentialité.
